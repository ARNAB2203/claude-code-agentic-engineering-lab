# Specification author

Use this skill before substantial implementation. Read `CLAUDE.md`, the closest existing specification, and affected API or UI contracts.

Create a specification with: problem statement, in/out of scope, functional and non-functional requirements, user stories, acceptance criteria, design constraints, data/API impacts, tasks, tests, risks, and a requirement-to-test table.

Avoid solution theatre: unknowns are questions, not invented decisions. A mock provider must remain labelled `mock`; do not promise real Claude execution without configured, verified credentials.
